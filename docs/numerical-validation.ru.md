# Численная проверка

## Независимые контрольные данные

`scripts/reference-solver.py` — отдельная реализация уравнений на Python 3,
использующая адаптивную пару Рунге–Кутты–Фельберга 4(5). Она не вызывает C++-ядро
и не использует его RK4. Дополнительные Python-пакеты и сеть не требуются.
Метод: [Fehlberg, NASA TR R-315, 1969](https://ntrs.nasa.gov/citations/19690021375).
Константы нижней атмосферы сверены с [реализацией PDAS](https://www.pdas.com/programs/atmos.py).

Верхняя атмосферная таблица является общими входными данными двух реализаций.
Поэтому сравнение проверяет численную согласованность реализации заданной модели,
а не достоверность этой таблицы или всей физической модели.

Для каждого сценария эталон считается с двумя допусками, различающимися в десять
раз. Проверяются разности: высота < 0,01 м, скорость < 0,0001 м/с, угол траектории
< 1e-9 рад, центральный угол < 1e-10 рад. Коэффициенты интегратора дополнительно
проверяются на `y'=y`. Зафиксированные результаты — `tests/core/reference_cases.inc`.

```text
python scripts/reference-solver.py --check
```

Без `--check` скрипт пересоздаёт эталоны; такое изменение требует проверки diff.
Побитовое совпадение генератора проверяется в текущем Python/Windows окружении;
основные C++-тесты сравнивают физические величины с допусками.

## Матрица

Девять сценариев: штатная программа, фиксированные найденные параметры, нагрузка
3500 кг, вертикальный участок 30 с, два варианта времени/угла поворота, углы 5°
и 30°, досрочное выключение на 570,123456789 с. Сценарий 30° выходит выше 300 км
и проверяет уведомление о границе атмосферы. Каждый сценарий проверяется при
максимальном шаге 1; 0,05; 0,01; 0,005 с — всего 36 сочетаний.

Критерии сравнения C++ и независимого эталона: высота 0,05 м, скорость 0,0001 м/с,
угол траектории 1e-7 рад, центральный угол 1e-8 рад. Это допуски проверенных
сценариев, а не универсальная гарантия для произвольных входов. Негладкие
аэродинамические зависимости могут давать немонотонное уменьшение ошибки по шагу.

Отдельно проверяются аналитическое изменение скорости по уравнению ракеты без
внешних сил, круговое движение в центральном поле и сохранение энергии, совпадение
событий ступеней с узлами программы, цели подбора 180/200/220/240/250/260/300 км,
отмена и лимиты. Для 180 и 200 км проверены досрочное выключение, остаточная масса,
точное воспроизведение найденных входов и уменьшение шага до 0,005 с.

## Контракт программы угла

По умолчанию `Parameters::programDomain = ProgramDomain::Bounded`: **весь** график
φ(t), включая внутренний экстремум квадратичного участка, должен оставаться в
0–90°. Достаточно проверить концы и вершину полинома; проверка не зависит от шага.
Штатный UI использует именно эту область. Ввод, ранее допускавший разворот на
сотни тысяч градусов, теперь отклоняется до запуска расчёта.

Для явного воспроизведения прежних экспериментальных программ API поддерживает
`ProgramDomain::LegacyUnbounded`. Это сохраняет математический полином, включая
его выбросы, и не означает физическую допустимость такого управления. В UI
режим не предлагается. Он используется в регрессии неудачной пробы оптимизатора.

Расчёт по-прежнему подбирает высоту и модуль скорости, без отдельного условия
нулевой радиальной скорости. Ограничение пространственного шага не является
оценкой локальной ошибки интегрирования; указанные тесты не меняют это свойство.
