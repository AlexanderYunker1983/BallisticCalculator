# Выпуск 2.1.0

`build-release.cmd` и `rebuild-release.cmd` собирают Release x64 и автоматически
выполняют тесты ядра, интерфейса, упаковки и отката. Версия приложения хранится
в `src/app/version.h`. Независимый численный эталон дополнительно проверяется
командой `python scripts/reference-solver.py --check` (нужен Python 3); Python не нужен для сборки
и запуска основных C++-тестов.

## Последовательность

1. До сборки сохраняется SHA-256 каждого исходного файла в
   `artifacts/qt-release/source-inputs.json`.
2. Сборка и тесты проходят до изменения установленной поставки.
3. EXE, DLL, плагины, документация и лицензии размещаются в новом
   `dist/staging-*/Release`. Smoke test выполняется из этой папки с очищенным PATH.
4. Архив исходников включает также генератор независимого эталона и скриптовые
   тесты. Упаковка отклоняется, если исходники изменились после начала сборки.
5. `build-manifest.json` содержит версию приложения, Qt и MSVC, UTC-время,
   Git-ревизию/признак изменений (если Git доступен), SHA-256 исходников и всех
   файлов поставки. Отсутствие Git обозначается `null`, а не фиктивной ревизией.
6. Перед заменой проверяются обязательные файлы, точное соответствие манифесту,
   архив исходников и содержимое переносимого ZIP. Неучтённые/повреждённые файлы,
   дубли имён и переходы через ссылки каталогов отклоняются.
7. Прежняя папка и ZIP перемещаются в `dist/previous-<идентификатор>`, затем
   устанавливаются новые. При исключении выполненные перемещения откатываются.

Каталоги `previous-*` сохраняются для возврата к прежнему выпуску. При ошибке
подготовки `staging-*` остаётся для диагностики. Это генерируемые каталоги,
исключённые из Git; их можно удалить после проверки нужного выпуска.

В каждом `previous-*` сохраняется `transaction.json` с путями и этапом операции.
Замена папки и ZIP не является одной файловой операцией: при завершении процесса
или отключении питания между перемещениями автоматический откат не выполняется.
Старые файлы остаются в резервном каталоге; журнал указывает их расположение.
При обычном исключении откат проверен на всех трёх границах замены.

## Повторная проверка готовой поставки

```powershell
./scripts/verify-release.ps1 -Directory ./dist/Release -WithArchive
./tests/scripts/release_tests.ps1
```

Скриптовые тесты используют собственные фикстуры под `artifacts/release-tests`,
не изменяя рабочий `dist/Release`. Проверяются успешная замена, повреждённые EXE,
ZIP и архив исходников, лишний файл, три отказа в процессе установки, изменение
исходников, выход из каталога артефактов и ссылка каталога.

Манифест обеспечивает проверку согласованности поставки. Он не является цифровой
подписью издателя. Чистая виртуальная машина без установленного SDK остаётся
отдельной проверкой: локальный smoke test исключает SDK из PATH, но не заменяет её.
