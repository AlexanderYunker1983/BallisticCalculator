# BallisticCalculator 2.2 — Qt 5.11.1

Нативное приложение C++14 / Qt Widgets для Windows x64. Пути в этом руководстве указаны относительно корня репозитория. Общий проект — `BallisticCalculator.pro`.

## Запуск и управление

Запускать `BallisticCalculator.exe` из папки поставки, сохраняя рядом DLL и каталог `platforms`. На Windows 10/11 используется системный Universal CRT; MSVC runtime и Qt-библиотеки включаются в поставку скриптом. Установка программ и изменение PATH пользователя не выполняются.

1. Открыть «Параметры ракеты…», указать полезную нагрузку и параметры трёх ступеней. Кнопка «Применить» сохраняет значения, «Отмена» отбрасывает изменения. Ниже полей показаны суммарные стартовая масса и запас топлива.
2. Задать длительность вертикального участка, время/угол поворота, целевую высоту и максимальный шаг.
3. Оставить «Подбирать параметры полёта» для автоматического поиска угла, времени поворота и выключения двигателя последней ступени. Для ручного расчёта снять флажок и задать «Выключение двигателя, с»; 0 («Всё топливо») означает полную выработку. Время считается от старта.
4. Нажать «Рассчитать» или Ctrl+Enter. «Остановить» и Esc отменяют текущий расчёт. При ошибке показывается причина; предыдущие успешные графики сохраняются.
5. Графики: колесо меняет масштаб, левая кнопка с перетаскиванием сдвигает область, двойной щелчок или «Сбросить масштаб» возвращает весь диапазон. Наведение показывает координаты ближайшей точки по X.

Массы заданы в кг; **масса ступени включает её топливо**. Тяга — Н. **Удельный импульс задаётся в м/с (Н·с/кг)**; в ядре это поле `exhaustVelocity`. Если исходное значение задано в секундах, для этого поля его нужно умножить на 9,80665. Времена — с, ввод угла — градусы. Целевая высота вводится в км; внутри ядра расстояния — м, углы — радианы.

Под результатами показаны фактическое время выключения и остаток топлива III
ступени. При досрочном выключении ступень и топливо остаются на борту. Графики
заканчиваются в момент выключения; последующий пассивный полёт не рассчитывается.
Пример для 200 км и критерии проверки — [в описании изменения](engine-cutoff.ru.md).

Числовые поля принимают точку и запятую. Tab переводит фокус между полями; в диалоге параметры проходятся по ступеням. Стрелки ↑/↓ меняют значение активного поля. Колесо над неактивным полем прокручивает окно, не меняя число. При ошибке в параметрах некорректное поле выделяется, а фокус переводится к нему. На небольших экранах и при крупном масштабе содержимое прокручивается; кнопки подтверждения диалога остаются доступны.

## Светлая и тёмная тема

По умолчанию приложение следует настройке **режима приложений Windows**. Изменение темы обновляет фон, поля, кнопки, подписи, сетку и линии графиков, а также уже открытые диалоги. Перезапуск не нужен; введённые данные, результаты и масштаб графиков сохраняются. Менеджер обрабатывает уведомления Windows и дополнительно проверяет настройку раз в секунду. Контрастная тема Windows имеет приоритет над обычной палитрой.

Для проверки или отдельного запуска можно явно задать `BallisticCalculator.exe --theme light`, `--theme dark` или `--theme system`. Без ключа используется `system`. Параметр действует только на этот запуск. Приложение читает системные настройки, но не меняет тему Windows. Оформление заголовка окна зависит от поддержки Windows; клиентская область переключается независимо от неё.

## Сборка

В корне репозитория выполнить `build-release.cmd`. Для полной пересборки с очисткой `artifacts/qt-release/native` — `rebuild-release.cmd`. Скрипты можно вызывать из любого рабочего каталога. Проверенные пути по умолчанию:

```text
QT_DIR=C:\Qt\Qt5.11.1\5.11.1\msvc2017_64
VCVARS64=C:\Program Files (x86)\Microsoft Visual Studio\2017\Enterprise\VC\Auxiliary\Build\vcvars64.bat
VC_REDIST_DIR=C:\Program Files (x86)\Microsoft Visual Studio\2017\Enterprise\VC\Redist\MSVC\14.16.27012\x64\Microsoft.VC141.CRT
```

Итог: `dist/Release/BallisticCalculator.exe` с полным комплектом библиотек и архив `dist/BallisticCalculator-Qt5.11.1-win64.zip`. Скрипт собирает Release x64, выполняет тесты, заново создаёт `dist/Release`, копирует Qt через соответствующий `windeployqt`, добавляет MSVC runtime, лицензии и проверяет вычисление/отрисовку всех вкладок из поставки. Содержимое `dist/Release` заменяется при сборке; весь каталог `dist` исключён из Git. Промежуточная сборка остаётся в `artifacts/qt-release/native`. В папку поставки входит `BallisticCalculator-native-source.zip` с использованными исходниками приложения, ядра и скриптами сборки. Для другого расположения SDK задать перечисленные переменные перед вызовом.

Поставку переносить целиком: EXE, Qt DLL, MSVC runtime, графические DLL, каталоги `platforms`, `styles`, `imageformats`, `iconengines`, файл `qt.conf` и лицензии. `qt.conf` задаёт поиск плагинов рядом с EXE, поэтому установленный Qt и изменение PATH на целевом Windows 10/11 x64 ПК не нужны. Общий скрипт `scripts/build-qt.cmd` также поддерживает ключ `--rebuild`.

Ручная сборка в **x64 Native Tools Command Prompt for VS 2017**, из отдельного build-каталога:

```bat
set "PATH=C:\Qt\Qt5.11.1\5.11.1\msvc2017_64\bin;%PATH%"
qmake <repository>\BallisticCalculator.pro CONFIG+=release CONFIG-=debug
nmake
```

`BallisticCalculator.pro` — общий проект `SUBDIRS`: сначала собирается `src/core/core.pro`, затем `src/app/app.pro`, `tests/core/core_tests.pro` и `tests/ui/ui_tests.pro`. Приложение и тесты используют одну статическую библиотеку; исходники ядра в потребителях повторно не компилируются. Ядро не зависит от Qt, тестовый адаптер использует Qt Test.

При указанной ручной сборке результаты расположены относительно build-каталога: `src/core/release/BallisticCore.lib`, `src/app/release/BallisticCalculator.exe`, `tests/core/release/core_tests.exe`, `tests/ui/release/ui_tests.exe`. Для Debug заменить `CONFIG+=release CONFIG-=debug` на `CONFIG+=debug CONFIG-=release`; библиотека называется `src/core/debug/BallisticCored.lib`. В Qt Creator в качестве запускаемой цели выбрать `BallisticCalculator`. Самостоятельная сборка и пример использования ядра описаны в [документации API ядра](core-api.ru.md).

Все файлы исходников — UTF-8. Включён `/utf-8` для MSVC. Для русских строк UI используется `QString::fromUtf8`: на проверенном сочетании Qt 5.11.1/MSVC 2017 wide-literal-конкатенация `QStringLiteral` давала неверные символы. Это дополнительно проверяется тестом Unicode-кодов русских подписей.

## Вычислительный алгоритм и интерфейс

Независимые проверки и ограничения программы угла описаны в
[численной верификации](numerical-validation.ru.md). Упаковка использует временную
поставку, манифест SHA-256 и откат: [порядок выпуска](release-validation.ru.md).

- **RK4:** время передаётся отдельно как `t`, `t+dt/2`, `t+dt`; алгебраические `phi`, `alpha`, Mach, масса, тяга и атмосфера вычисляются для каждого промежуточного состояния.
- **Разделение ступеней:** шаг заканчивается точно на событии. Все этапы этого шага используют прежнюю ступень; сохранённая точка на границе и следующий шаг используют следующую. При полной выработке последняя ступень отделяется, масса равна полезной нагрузке. При досрочном выключении её сухая масса и остаток топлива сохраняются. События программы поворота и выключения тоже учитываются.
- **Начальная точка:** содержит действительные массу, плотность, ускорение и перегрузку.
- **Подбор:** две невязки (высота и модуль скорости), три параметра (угол, время поворота и выключения). Численная матрица чувствительности задаёт поправку минимальной нормы с ограничениями параметров и уменьшением шага при отсутствии улучшения. Проверяются оба критерия. Финальная траектория строится именно из возвращаемых входов и проверяется повторно.
- **Валидация:** конечность значений, положительные параметры, топливо меньше полной массы ступени, порядок времён, достаточная стартовая тяга, диапазоны шага/цели.
- **Ограничения:** по умолчанию 40 итераций, 250 прогонов, 2 миллиона шагов на прогон, 60 секунд на запуск. Шаг 0,000001–1 с; длительность ступеней суммарно не более 24 часов. Недостижение цели возвращается как отдельный статус.
- **Потоки:** глобальные изменяемые расчётные данные отсутствуют. Отмена использует atomic-флаг, проверяемый внутри вычисления. UI обновляется после завершения worker в GUI-потоке; закрытие окна запрашивает отмену.
- **Интерфейс:** «Отмена» диалога не применяет значения; ошибки отображаются; ввод принимает точку и запятую без зависимости от локали; поля хранят числа, не строки.
- **Графики:** полные точки сохраняются; прорисовка группирует их по экранным колонкам с сохранением минимума/максимума и порядка. Сглаживающие сплайны, создающие искусственные выбросы около разрывов, не используются.

## Физическая модель и её ограничения

Нижняя атмосфера 0–86 км вычисляется по семислойной модели COESA 1976 в геометрической высоте с константами реализации [PDAS](https://www.pdas.com/atmos.html), [опубликованная реализация и константы](https://www.pdas.com/programs/atmos.py). Это устраняет аномальную температуру на 5,5 км и другие несогласованные значения нижней части старой таблицы. Исходный стандарт: [NASA, U.S. Standard Atmosphere 1976](https://ntrs.nasa.gov/citations/19770009539). Это намеренное изменение численных данных, а не побитовый перенос таблицы.

Выше 86 км сохранены табличные данные исходной модели от 90 до 300 км; участок 86–90 км соединён линейно с новой нижней моделью. Это **комбинированная инженерная модель**, не полная реализация COESA для верхней атмосферы. Между метровыми узлами выполняется линейная интерполяция. Выше 300 км используются крайние значения и показывается сообщение; нечисловая высота отклоняется до индексирования. Отрицательная высота при запросе таблицы ограничивается уровнем моря; падение траектории ниже поверхности контролируется отдельно solver.

Перегрузка теперь рассчитывается как модуль негравитационного ускорения, делённый на `g0`, вместо `dV/dt/g0+1`. Сохранены исходные зависимости аэродинамических коэффициентов, опорная площадь и геометрия уравнений. Сингулярность углового уравнения при малой скорости, как и прежде, обходится фиксированием угловой производной при `|V|≤0,5 м/с`.

Подбор обеспечивает **высоту и модуль скорости**, с допусками 100 м и 0,1 м/с. Отдельного условия на нулевую радиальную скорость нет, поэтому результат не называется подтверждённой круговой орбитой. Изменение шага ограничивает пространственное продвижение примерно 10 метрами, но не является оценкой локальной погрешности. Независимая физическая верификация всех уравнений в этот перенос не входит.

## Проверки и эталон исправленной версии

Тесты проверяют время RK-этапов на аналитической задаче, четвёртый порядок на гладком уравнении, атмосферные опорные точки, недопустимые входы, сходимость по шагу, точные события, согласованность входов/траектории, независимость одновременных запусков, отмену и лимиты. GUI-тесты проверяют русские подписи, обе локали/разделителя, подтверждение/отмену диалога, повторный запуск, сохранение предыдущего результата при ошибке, графики и закрытие во время расчёта.

Один измеренный Release-прогон исправленного ядра со штатными входами:

```text
Число вычислений траектории: 11
Число точек:                188270
Конечная высота:            249999.821605668 м
Конечная скорость:          7753.712721681 м/с
t1:                        353.527598425 с
phi1:                      9.076611858 градусов
```

Повторный прогон по полным возвращённым входам воспроизводит траекторию. При уменьшении максимального шага с 0,01 до 0,005 с изменение конечной высоты около 0,00183 м, скорости около −0,000000065 м/с на данном сценарии. Это численная проверка одного режима, а не доказательство точности для всех входов.

Тестовые журналы находятся в `artifacts/qt-release/native/tests/core/core-tests.txt` и `artifacts/qt-release/native/tests/ui/ui-tests.txt`. PNG пяти вкладок — в `artifacts/qt-release/screenshots/`.

Полная проверка 29.09.2026 после обновления интерфейса: **21 passed** в CoreTests, **19 passed** в UiTests, ошибок нет (счётчики Qt Test включают init/cleanup). Поставка успешно выполнила smoke test с удалённым Qt из PATH. Проверены светлая и тёмная темы, снимки при масштабах 100%, 150% и 200%; переключение между физическими мониторами с разным DPI отдельно не проверялось. Штатный расчёт в Release занимал около 0,6 с на этом ПК.

При выделении ядра обе конфигурации **Release и Debug** прошли тогдашние 21 + 13 проверок, Debug — в каталоге с пробелом. Пример из `docs/core-api.ru.md` собран напрямую через MSVC и связан с `BallisticCore.lib`; он выполнил штатный расчёт без Qt в PATH, а `dumpbin /dependents` подтвердил отсутствие Qt DLL. Проверки нового интерфейса дополнительно покрывают переключение палитры в открытых окнах, сохранение данных и масштаба, смену темы при работающем расчёте, контраст текста, прокрутку небольших окон и защиту полей от случайного вращения колеса.

Автоматизированная проверка собранного EXE:

```bat
BallisticCalculator.exe -platform windows --smoke-test <screenshot-directory>
```

В этом режиме окно не показывается на экране: выполняется расчёт, сохраняются пять снимков и возвращается код 0 при успехе. Проверка поставки выполняется на текущем ПК с Qt удалённым из PATH и очищенными `QT_PLUGIN_PATH`/`QT_QPA_PLATFORM_PLUGIN_PATH`; плагины находятся через локальный `qt.conf`. Чистая виртуальная машина и другие ОС пока не проверены.
